An evening project.
A companion for many more.

Start with a Raspberry Pi, a touchscreen and a place to watch the sky. The installer sets up the application and its kiosk for your desktop user.

Upgrade to 1.3

Version 1.3 expands the object catalog and adds an optional local Astrometry.net fallback with matched-star verification. Download a ZIP backup from Settings, then run:

On your Raspberry Pi
git fetch --tags origin
git checkout v1.3
.venv/bin/pip install -r requirements.txt
sudo systemctl restart astro-panel
systemctl --user restart astro-kiosk

Tap ASTRO to confirm Version 1.3. Photos, preferences, dimming and display rotation are retained. To roll back, check out v1.2 and restart both services. Release 3 · v1.3

Upgrade to 1.1

Create and download an application ZIP backup first. In your existing checkout, fetch the release and restart the application and kiosk. User photographs and settings remain outside the checkout.

On your Raspberry Pi
git fetch --tags origin
git checkout v1.1
.venv/bin/pip install -r requirements.txt
sudo systemctl restart astro-panel
systemctl --user restart astro-kiosk

The old brightness value is migrated automatically into the new profile. The original percent field is retained for rollback. To return to the prior application, check out v1.0 and restart both services; preserve the current data directory. The release does not change the kernel, display rotation or touch mapping.

What you need

  • Raspberry Pi 4 with at least 4 GB RAM, or newer, with a suitable power supply and microSD or other supported storage.
  • 64-bit Raspberry Pi OS Desktop, Python 3.11 or newer, and a working Wayfire or labwc session. Raspberry Pi OS Lite does not provide the required desktop.
  • Original official 7-inch Touch Display or 7-inch Touch Display 2, using the correct DSI ribbon cable for your Pi.
  • A network connection. Allow at least 5 GB free to install the optional solver, plus room for photographs and backup ZIPs. The app reserves 2 GiB for the system.

Verified hardware: Raspberry Pi 4B, 4 GB, 64-bit Bookworm, Wayfire 0.7.5, original 800 × 480 DSI display at 180°, kernel 6.12.96+rpt-rpi-v8. Touch Display 2 and labwc have software checks; physical testing remains pending.

Install the application

01 / Run as your normal desktop user

Start with an updated Raspberry Pi OS that supports your display. Open a terminal on the Pi or connect by SSH. The checkout is named RaspAstroDisplay when cloned below.

On your Raspberry Pi
sudo apt update
sudo apt install -y git
git clone https://github.com/RAHoebe/RaspAstroDisplay.git
cd RaspAstroDisplay
bash deploy/install.sh

The installer creates the Python environment, system and user services, and backlight permissions for your user and checkout path. Its display wizard detects the panel and asks for rotation, interface size and cursor visibility. Configuration changes receive dated backups.

02 / Start the desktop automatically
On your Raspberry Pi
sudo raspi-config

Enable desktop autologin, then reboot. The dashboard opens automatically in Chromium on the Pi. The backend service runs without sudo.

Add local star matching

03 / Optional, for aligned photo comparison
On your Raspberry Pi
bash deploy/install-solver.sh

This downloads the official ASTAP command-line solver and D50 star database into ~/.local/share/astap. The database download is approximately 860 MB. Downloaded archives remain in ~/.cache/astro-installer. ASTAP and its database are separately supplied components; see their sources and licenses.

After installation, open a suitable deep-sky capture and use Compare → Align locally. No cloud solver account or API key is needed.

For difficult captures, also run bash deploy/install-astrometry.sh. This installs Debian Astrometry.net plus approximately 334 MB of Tycho-2 indexes for roughly 0.5-8 degree fields. Photographs stay local.

Set your location

Use the touchscreen or open http://<your-pi-hostname>.local:8080/ from another device on the same network. If hostname resolution is unavailable, use the Pi’s IP address.

New installations start in English (US) at Greenwich. In Settings → Location & language, choose your observing location and preferred language. A saved language becomes the default for new browsers; a browser may retain its own selection.

Open a target and choose your telescope. Built-in profiles cover DWARF II and Seestar S50 Pro; add another in Settings using its field width and height in degrees. For a new panel or another orientation, follow the display guide.

Update without losing your photos

Run these commands inside your checkout. Application state is stored separately, so code updates preserve photographs and settings. Keep a recent downloaded backup.

On your Raspberry Pi
git pull --ff-only
.venv/bin/pip install -r requirements.txt
sudo systemctl restart astro-panel
systemctl --user restart astro-kiosk

If something needs attention

On your Raspberry Pi
systemctl status astro-panel
journalctl -u astro-panel -n 50 --no-pager
systemctl --user status astro-kiosk
python3 deploy/display.py status

Browser cannot reach the panel

Check that both devices share a network and that astro-panel is running. Try the IP address. Local hostnames and addresses are detected automatically; after an IP change, restart the backend if a numeric address is rejected. For additional aliases, set comma-separated ASTRO_HOSTS in a systemd override.

Image is rotated but touch is wrong

Run the display wizard and reboot so output, touch mapping and kiosk dimensions agree. Legacy Bookworm upgrades can also retain a conflicting touch overlay; the touch recovery notes explain the verified case.

Reference or weather unavailable

Check the network and source timestamps. The app keeps cached data and reports stale or unavailable information. A survey outage does not remove your own photographs.

Run a development copy

The app uses Python and plain HTML, CSS and JavaScript, with no frontend build step. On Linux:

Development / Linux
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
ASTRO_BIND=127.0.0.1 OPENBLAS_NUM_THREADS=1 .venv/bin/python app.py
.venv/bin/python -m unittest discover -s tests -v

On Windows, use .venv/Scripts/python and PowerShell environment variables. Development state defaults to .runtime/. Configurable environment variables include ASTRO_STATE, ASTRO_BIND, ASTRO_PORT, ASTRO_HOSTS, ASTRO_SOLVER_HOME and ASTRO_SOLVER. Translations live in static/locales.json.

The GitHub Pages site is plain static HTML in doc/. Preview it with python -m http.server 8090 --directory doc. Its deployment workflow publishes only that directory. Working notes in plan/ and private helper scripts in toolslocal/ are ignored by Git.
