The Touch Display 2 landscape profile provides about 853 × 480 logical browser pixels at 150% scale; compact 125% scaling provides 1024 × 576. All four rotations are available for both panels. At 90° and 270°, native width and height swap. Portrait layouts scroll when needed.

Use a Pi 4 with 4 GB RAM or newer, 64-bit Raspberry Pi OS Desktop and current KMS graphics. Connect one supported DSI display during configuration.

Choose a rotation that suits your frame

On your Raspberry Pi
python3 deploy/display.py wizard
sudo reboot

Run from the checkout as your desktop user. The wizard offers English or Dutch, detects the panel’s connected DSI mode, and lets you choose rotation, interface size and cursor visibility. If more than one touchscreen is present, select the device attached to the panel.

Before saving, it previews the result and creates a dated backup in ~/raspdisplay-backups/. The selected profile is stored in ~/.config/astro-display.json and read when the kiosk starts.

Preview or configure from the command line

On your Raspberry Pi
python3 deploy/display.py preview touch2 --rotation 270
python3 deploy/display.py apply touch2 --rotation 270 --cursor hidden
python3 deploy/display.py status

preview makes no changes. Without a saved profile, the kiosk uses original-display dimensions and leaves desktop rotation as configured. Display configuration is handled by the setup tool, not by the web interface.

When your new panel arrives

  1. Update Raspberry Pi OS through its supported package-management path with the current panel attached. display.py status checks whether the Touch Display 2 overlay is installed.
  2. Run sudo poweroff, disconnect the power, then change the panel and cable following Raspberry Pi’s instructions.
  3. Boot, run the wizard over SSH or in a terminal, and reboot to apply display, touch and kiosk settings together.
  4. Check that top-right Settings and bottom-left Tonight respond at their visible positions.

Follow the official instructions for the original Touch Display or Touch Display 2. Use the correct ribbon cable for your Pi generation.

Touch mapping and cursor

Wayfire: the wizard writes the output transform and touchscreen-to-output mapping in ~/.config/wayfire.ini. Wayfire applies the display transform to mapped touch. Adding an extra XInput or udev rotation matrix would rotate coordinates twice.

labwc: the wizard writes touch mapping and the corresponding libinput calibration matrix in ~/.config/labwc/rc.xml. Kiosk startup applies the output transform using wlr-randr. Unrelated settings are preserved. This adapter follows labwc’s configuration reference; physical verification is pending.

A transparent Xcursor theme hides the pointer from desktop startup, including before the first touch. Select a visible cursor in the wizard if you use a mouse. The kiosk page also hides its cursor through CSS.

A legacy overlay can block native touch

On the tested Bookworm upgrade to kernel 6.12.96+rpt-rpi-v8, the old dtoverlay=rpi-ft5406 line prevented native touch from probing. Commenting that legacy line in /boot/firmware/config.txt, while retaining display_auto_detect=1 and dtoverlay=vc4-kms-v3d, restored the original panel’s touch. Its input then appeared as 10-0038 generic ft5x06 (79).

For a similar failure, inspect journalctl -b -k and /proc/bus/input/devices before changing overlays, and back up boot configuration first. Device names are detected; event numbers are not hardcoded. If Wayfire sees the device but lacks mapping, run python3 deploy/display.py touch-only and restart the desktop.

Return to a known configuration

Use SSH to rerun the wizard or restore wayfire.ini / rc.xml and astro-display.json from the same dated backup, then reboot. A no-previous-profile marker means reverting also requires removing the newly created ~/.config/astro-display.json.

Validation boundary: the original panel, rotated 180°, has been checked on real hardware with working touch and hidden cursor. Touch Display 2 dimensions, rotations and configuration have automated checks. The new physical panel and labwc session have not yet been verified.
